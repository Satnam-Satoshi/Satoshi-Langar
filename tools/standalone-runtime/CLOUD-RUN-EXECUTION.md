# Dormant Cloud Run execution observer

Source-only GET adapter. No provider account, token, resources, billing or deployments were used. `networkEnabled:false` is the default. Tests use synthetic HTTP responses. This is not runtime attestation or permission to dispatch/publish.

`createCloudRunExecutionObserver` takes fixed project/region/job/execution, one exact image URL with `@sha256:` digest, and one service account. The independent token resolver must later use approved runtime identity, not credentials in environment/source/logs. `observe()` performs one bounded GET to the fixed `run.googleapis.com` execution resource. It rejects redirects, errors, oversized data, wrong identities, multiple containers/tasks, mutable image tags, deletion/expiration markers and invalid/future timestamps. Provider UTC timestamp precision 0/3/6/9 digits is preserved and compared at nanosecond precision. No automatic retries, list operation, mutations or token creation exist. An explicit later read can reconcile an observation; it never creates an execution.

Output includes execution resource name, immutable UUID, parent job, exact image and service account, create/start/completion times, observation interval and response byte hash. It intentionally does not return raw environments, labels, annotations or credentials. All outputs keep runtimeAttestation/sourceProvenanceVerified/fullTemplateVerified/executionSuccessVerified false. Completion time alone is not success. Extra command/args/env/volume/retry configuration is not validated by this narrow projection. A separate reviewed deployment-template gate must verify it before any effects.

## Official contract and limits

- Runtime lookup hints: https://docs.cloud.google.com/run/docs/container-contract . Jobs provide CLOUD_RUN_JOB, CLOUD_RUN_EXECUTION, CLOUD_RUN_TASK_INDEX, CLOUD_RUN_TASK_ATTEMPT and CLOUD_RUN_TASK_COUNT. Environment values are not signed proof of the calling process.
- GET resource and permission: https://docs.cloud.google.com/run/docs/reference/rest/v2/projects.locations.jobs.executions/get . Requires run.executions.get; path fixes project/location/job/execution.
- Immutable execution configuration: https://docs.cloud.google.com/run/docs/reference/rest/v2/projects.locations.jobs.executions . Its snapshot matters rather than the current mutable Job alone.
- Image and service-account fields: https://docs.cloud.google.com/run/docs/reference/rest/v2/TaskTemplate and https://docs.cloud.google.com/run/docs/reference/rest/v2/Container . The generic image field is not a separately documented resolved-digest attestation, so this adapter requires literal exact digest equality and holds tags.
- Runtime identity: https://docs.cloud.google.com/run/docs/securing/service-identity . Service-account authentication identifies a principal, not a documented cryptographic claim of job/execution/image/source provenance.

The worker's trusted observeRuntime boundary additionally expects operation association, exact source commit and reviewed build-provenance binding, and a bounded evidence validity window. This raw observer does NOT satisfy that boundary directly. Operation association requires independently authenticated operation response; source-to-image linkage requires retained reviewed CI provenance. Labels, SOURCE_SHA environment variables, source location or arbitrary local configuration cannot manufacture that evidence. A matching execution accessible to the service account does not prove this process is that execution. Deployer/service-account trust and independent control-plane observation remain necessary. No actual API compatibility or unattended runtime has been demonstrated.

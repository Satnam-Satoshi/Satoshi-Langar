# Dormant campaign → platform draft → private reservation composition

`createMarketingPreparationRuntime` uses the actual pure campaign generator, current bounded platform validator and concrete private Firestore reservation store. Both preparation and reservation default off. No Buffer mutation, timer, subscriber capture, OAuth, credential resolver or post executor is provided. Generated Buffer input has `saveToDraft:true`; it is not even sent to a drafting API. Every result remains `executeAllowed:false` and `schedulingAuthorized:false`.

The independently reviewed constructor fixes the two project channels, SDK/store/claim, clock and authority loaders. No personal channel is discovered or inferred. `advance({campaign,selection})` takes the generator's complete input and an exact campaign/issue/story/platform/due time/queue observation selection. It copies bounded plain data, Maps and evidence bytes before any await, rejecting accessors and custom iterators. The actual generator preserves the entire backlog and cursor; selection cannot skip eligibility checks. At most one new private reservation is attempted per call.

The trusted `loadPlatformEvidence({draft,dueAt,channelId})` returns exactly `{policy,expectedPolicySha256,accountLimits,publishedEvidence}` as specified in MARKETING-PLATFORM-POLICY.md. The runtime derives the request from the exact generated copy, canonical URLs, alt text and hashtag tokens, never from a supplied request body. It independently checks the media digest against the generator. Campaign policy and technical platform policy are separate pinned documents; neither hash authenticates its author. Dynamic quota, connected identity, public-readback evidence and factual/tag relevance still require independently authenticated loaders. No status string, synthetic fixture or generated boolean supplies that authority.

After the platform loader, current finite/nondecreasing time and preparation freshness are rechecked. Future due time is bounded by the separate content horizon, not the short queue/public-readback observation lifetime. The store independently rechecks publication, policy, reconciled canonical queue, inventory revision, stops, prior attempts and NY-date slots at transaction time. The existing direct Buffer `complete:false` capture is not converted into reconciliation. Unknown or unbound posts, drafts, stopped campaigns and missing historical inventory hold. An existing exact reservation is read back unchanged; new content cannot replace it. A batch of two drafts is not a coverage cap. Later reservations require fresh independently reconciled inventory, not a locally incremented queue assertion.

After reservation, the actual platform validator runs again against the final clock, so earlier platform-policy/account/public-proof or quota-window expiry cannot be mislabeled current. Post-reservation expiry is labeled noncurrent; invalid/backward clock holds with `reservationMayExist:true` and latches that instance. Private callback errors are not returned verbatim. Injected authority/SDK methods can perform reads, so `providerCalls:null` is used after their invocation rather than claiming no network activity. No provider mutation is implemented by this module; the reservation is private datastore state, not a queued or published post.

Growth is limited to the generator's verified canonical RSS link or an independently approved, currently tested DOI/unsubscribe route. It never treats the existing closed signup page as active, enrolls anyone, imports subscribers or claims consent from a click. Zero automated mentions, DMs, replies, follows or bought engagement. Future execution must revalidate current platform limits, evidence, actual account quotas, media availability, campaign authorization and stops; this draft/reservation is not enduring permission to send.

Synthetic end-to-end tests use the real generator, policy validator and reservation implementation over a fake SDK and separately labeled authority fixtures. No live history, accounts or credentials are included. A true canonical-ledger migration, authenticated queue/review loaders, supported posting/public-observation executor and operational scheduling remain unimplemented rollout prerequisites. Runtime startup remains disabled.

The full returned backlog/cursor still needs an independently authenticated durable upstream checkpoint; this reservation store persists only the selected reservation and retained cadence/history. Returning all entries is not proof that all-story backlog storage or campaign delivery is operational.

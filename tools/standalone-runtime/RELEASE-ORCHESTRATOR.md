# Dormant concrete preview → QA → private archive slice

`createReleaseOrchestrator` composes existing concrete candidate-ref admission/update, Firestore ref and Vercel preview journals, Vercel create/read-only identity, actual four-artifact release QA, private frozen QA phase storage, and concrete Drive QA archive helper. No arbitrary adapter claiming `verified:true` substitutes for these implementations. All network/mutation flags default false; disabled `advance()` touches no SDK/provider/credential methods.

Inputs are independently fixed candidate `pins`, `qaTemplate` (existing release QA plan excluding only deploymentId/previewHostname), projectName, branch-hook policy digest, common Firestore store/claim, exact GitHub/Vercel/Drive transport boundaries, approvals and clock. Exact source, baseline commit, date/revision and four artifact digests crossbind before effects. Template shape is validated before ref mutation. Preview approval and source admission are independently injected authority callbacks from the existing adapter contract. Structural candidate observation does NOT generate them or establish semantic/source authority.

`advance()` first updates the existing candidate ref using full actual candidate object observation and the durable ref journal. It then creates or reconciles one preview using the durable Vercel journal. Deployment ID comes from durable provider response; hostname comes from actual source/project/branch-bound deployment GET. Only these provider-generated fields complete the QA plan. Actual preview artifacts, edition route and existing production baseline are read by `createReleaseQa`.

Before archival, exact canonical QA JSON is frozen into an immutable private Firestore phase row. The actual archive helper uploads those exact bytes through the inventory-backed upload journal, verifies owner-only metadata/version/actual bytes, and saves the exact receipt. A restart reads the frozen proof instead of running a timestamped new QA/upload. Unknown preview or upload outcomes never repeat their provider mutation. Missing indexed state and orphan rows hold. `reconcile()` is read-only, resolves only already frozen proof/archive state and can report stale proof without renewing it. It does not complete a missing phase write. No private Drive locator is returned by the orchestrator.

## Explicit scope limits

Result `preview-qa-archived` is NOT a complete release. `promotionAllowed` and `publicationVerified` remain false. `promote()` always holds. Existing promotion recomputes final QA after its durable intent, and that final pre-POST proof is not yet composed with this archive phase. Archiving an earlier preview proof is not represented as satisfying that gate. Public-domain post-promotion readback and its archive remain uncomposed. Optional `objectPlan` and independent `loadObjectApproval` compose actual Git-object creation before ref update. Without a plan, the explicit existing-candidate mode expects the immutable candidate commit already present and actually verifies it before ref update. No source-to-image or editorial authority is invented.

## Private phase journal

`createFirestoreReleasePhase` requires independently existing root `newsroomPrivateReleaseQaV1/inventory`, generation `standalone-release-qa-v1`, with `{schemaVersion:1,generation,initialized:true,revision,claims:{}}`. This is a schema description, never an instruction to reset lost history. Rows are `newsroomPrivateReleaseQaProofsV1/<SHA256(identity)>`, generation `standalone-release-qa-proof-v1`. Identity binds sourceCommit, projectId, artifact manifest digest and full pinned configuration digest including archive destination. No bootstrap/rotation/deletion API exists.

The only transitions are absent genuine new key → version1 frozen proofJson → version2 same proofJson with exact private receipt. Root index hashes and versions bind each row. First freeze is atomic under SDK transaction; only one concurrent caller wins. Every write validates existing controller owner/fence/lease/emergency stop and rechecks immediately before writes; the controller is not modified. Unknown commit latches that instance's writes, while reads remain available. Indexed zero/null state, known missing rows, orphan rows, different proof bytes and rollback hold. Capacity100 lifetime identities, root terminal safe integer readable but increment held. QA bytes limit64KiB; existing control payload independently bounded512KiB before parse, not passed through small identity serialization.

No Firestore transaction fences GitHub/Vercel/Drive externally. Branch writers/hooks must be independently reviewed and controlled; credential resolver, SDK and HTTP adapters are trusted boundaries. Actual service IAM/enrollment/initialized inventory migration are prerequisites, not proven by mocks. Retention is provider-policy dependent and not WORM. Tests exercise actual composed adapters with synthetic Git objects, mocked provider streams, fake serialized SDK transactions and real exact bytes. No actual cloud calls, provisioning, enrollment, or production changes were performed.

## Optional concrete Git-object phase

`objectPlan` must pass `prepareGitObjectPlan` and its pins must exactly equal orchestration pins. The concrete `createFirestoreGitObjectJournal` and `createGitHubCandidateObjects` are constructed with the same fixed SDK/control claim and transport. Each `advance()` performs at most one object POST and returns `candidate-object-prepared-progress`; only a subsequent full actual provider candidate observation proceeds to ref/preview. Unknown object results hold without automatic retry or finalization. No callback supplies an eligibility boolean. The independently approved object metadata/data-sharing policy remains required by the adapter. The plan digest participates in the immutable orchestration configuration identity.

The full synthetic integration test uses the existing object fixture's real local Git DAG, concrete object journal and mock provider with initially absent candidate objects, then the same SDK store through candidate ref, preview, QA freeze and Drive archive. It verifies one POST per object, one ref update, one preview and one archive, and no repeated mutations after restart. The fixture exposes its synthetic SDK configuration only for this composition. No real GitHub commit or provider resource was created. Promotion remains held.

Final result freshness is checked after the optional archive phase save using strict finite canonical UTC. The final clock cannot precede either the original proof or archive readback observation, and cannot upgrade an archive helper's `fresh:false`. Expiry during the save yields a stale archived result; invalid/backward clocks hold instead of returning a verified-looking result.

# Offline signed review authority (dormant)

`createSignedReviewAuthority({trustPolicy,clock})` exposes only synchronous `bind({signedReview,configuration,reviewEnvelope,collection})`. Missing policy returns `review-trust-not-configured`. There is no signer, key generation, credential resolver, network, enrollment, persistence or activation API. Test keys are synthetic and created in memory only.

The independently enrolled policy fixes: `algorithm:'Ed25519'`, canonical DER SPKI public key as base64 and its SHA256, reviewer reference, `purpose:'standalone-editorial-review-v1'`, repository `Satnam-Satoshi/Satoshi-Langar`, exact source commit and configuration/capture/review digests, notBefore/expiresAt, maxValiditySeconds (1–86400), and revoked boolean. This policy must come from independent reviewed enrollment. Supplying a public key or hash in the same untrusted package as a review does not establish trust. The module never enrolls it.

Signature input is UTF8 `LTC-STANDALONE-EDITORIAL-REVIEW-V1\n` plus recursively key-sorted JSON of the exact payload: schemaVersion1, keySha256, reviewerReference, purpose, repository, sourceCommit, configurationSha256, collectionSha256, reviewSha256, issuedAt, expiresAt. `signedReviewPayloadBytes` produces these bytes for an external signing workflow but never signs. Envelope is exactly `{algorithm:'Ed25519',payload,signatureBase64}`. Signature must be canonical base64 encoding of64bytes; key must be canonical Ed25519 SPKI DER. Other algorithms, extra fields, getter-bearing objects and excessive inputs reject. Time values use exact millisecond UTC ISO. Future issuance, expiry, revocation and reverse clock reject. Payload expiry is bounded by policy and validity duration.

After signature verification, actual `bindReviewedEditorial` validates raw review/config records and retained capture bytes against the independently pinned digests. Reviewer reference must match and signature issuance cannot precede review completion. Final expiry intersects review/source freshness and policy/signature expiry. The returned binding is consumed by the existing retained editorial pipeline in integration tests; missing sources remain gaps and historical event dates remain unchanged.

Success `signed-review-bound` sets `signerAuthenticated:true` only under the independently enrolled key policy. It does NOT establish truth, adequate research, owner release permission, OAuth consent, source-to-image provenance, authenticated execution, or production readiness. Those flags remain false, and existing activation gates are unchanged. Binding itself retains its existing assurance-limited fields. No real trust enrollment or review was signed or authenticated in this work.

## Operational design and remaining work

An owner-approved enrollment process must select who may review, securely maintain the public key and revocation state, and protect the private signing key outside this package. An external signer reviews exact retained capture/config/review digests and signs this payload. Each release receives an independent policy pin with bounded validity; reusing a verifier does not refresh revocation from a remote authority. The caller must load current policy independently and must not treat a historical success result as current permission. Rotation/revocation distribution and production wiring are not implemented.

CI build attestation is a separate trust problem: verify the expected CI issuer/workflow and source-to-image subject using a reviewed attestation verifier and independently trusted identity policy. A custom editorial signature cannot substitute for CI provenance, and repository access or a caller digest cannot establish either identity. No GitHub attestation implementation or live verification is claimed here.

Results include private editorial/capture material in `binding`; do not log or publish full results. Bounded generic holds do not expose provider data or secrets. Tests verify cryptographic substitution, algorithm confusion, noncanonical signatures, time/revocation, accessors, byte bounds and real binder/pipeline composition offline.

Derived editorial policy Maps are clamped to the minimum signature, trust-policy and existing review/source deadline, and derived freshness bounds expose that same deadline. Consequently, later retained-pipeline consumption rejects expired signature authority even if the original review record remains fresh. Original signed records, source dates and original policy inputs are unchanged. This expiry propagation does not provide revocation polling; current revocation still requires re-verification under independently loaded policy.

# Dormant private marketing reservations

`createFirestoreMarketingSchedule({Firestore,expectedProjectId,expectedDatabaseId,claim,clock,authorityLoaders:null,mutationEnabled:false})` provides `reserve`, `read` and `capacity`. It prepares private reservations only. Every result has `executeAllowed:false`; no Buffer API, scheduler activation, subscriber mutation, credential lookup, source fetching or posting exists. Existing historical ledgers are not imported/read/reset by this module.

## Exact input and independent authority

`reserve({draft,dueAt,queueObservationSha256})` consumes the actual prepared generator draft. Draft fields are exactly `key,campaignId,issueId,storyId,storyContentSha256,platform,storyUrl,text,contentSha256,media,sourceEvidenceSha256,publicationReceiptSha256,policySha256,preparedAt,expiresAt,contentExpiresAt,growthUrl,growthEvidenceSha256,executeAllowed`. Media is exactly `{url,sha256,bytes,width,height,alt}` and must be a canonical hosted PNG1080×1350 ≤5MiB. Optional growth fields are both null or independently verified canonical owned RSS/subscription URL plus evidence digest. Source dates remain in generator coverage, not altered or redated by this store.

Caption bytes are SHA-checked; source/media/publication/policy/growth identities remain immutable. This store does not replay semantic source review or actual media readback: its coordinator must compose the actual validated generator and independent platform-policy checker. An arbitrary draft with matching self-computed hashes is not authorization. `dueAt` is strict millisecond UTC; the NY date is derived with Intl/America_New_York, including DST. `draft.expiresAt` is checked now (fresh preparation window); future dueAt must precede `contentExpiresAt` and all five independently approved source/tag/media/content/authorization deadlines.

Missing `authorityLoaders` holds. The constructor captures exactly three independently trusted read-only callbacks:
- `readPublication({receiptSha256})` → `{status:'published-edition-receipt-verified',receiptSha256,issueId,checkedAt,expiresAt,storyBindings:[{storyId,storyContentSha256,storyUrl}],nonAtomic:true}`.
- `readPolicy({policySha256})` → `{status:'marketing-preparation-policy',policySha256,campaignId,channelSha256,checkedAt,expiresAt,paused,platformStops:{X,Instagram},routinePerPlatformNyDay:1,sourceDeadline,tagDeadline,mediaDeadline,contentDeadline,authorizationDeadline}`.
- `readQueue({observationSha256})` → `{status:'queue-scope-reconciled',observationSha256,captureSha256,canonicalLedgerSha256,policySha256,channelSha256,inventoryRevision,checkedAt,expiresAt,statusScope:['draft','needs_approval','scheduled','sending','error','sent'],nonAtomic:true,unresolvedPlatforms:[],posts:[{platform,status,dueAt,sentAt,storyKeySha256}]}`.

These statuses/hashes do not authenticate themselves. The external coordinator must supply authenticated provenance and complete canonical reconciliation. Existing direct queue-scope tools deliberately return incomplete/canonicalLedgerBound:false; this module does NOT upgrade them. Their raw output is rejected. Observations must be no more than60seconds old and unexpired at reservation; their short expiry does not limit a later dueAt. Unbound posts, drafts, needs-approval, sending, errors and unresolved platform attempts conservatively hold that entire platform. Existing scheduled/sent posts consume NY-day slots; an already queued story blocks another reservation even on another day.

## Durable preservation and cadence

Existing independently initialized root is `newsroomPrivateMarketingScheduleV1/inventory`, generation `standalone-marketing-schedule-v1`. Schema fields: `schemaVersion:1,generation,initialized:true,revision,canonicalLedgerSha256,policySha256,channelSha256,paused,platformStops:{X,Instagram},unresolvedPlatforms,retainedSlots,claims`. This describes a reviewed migrated state, NOT permission to create/reset an empty root. Migration, ownership, old publisher stops and complete historical slots/attempts must be reconciled separately. Missing root holds.

`retainedSlots` indexes SHA256(canonical `[platform,NYdate]`) to `{platform,nyDate,historySha256}`. It never changes here. Existing pauses/stops and unresolved platforms never clear here. `claims` indexes stable reservation key SHA256(canonical `[campaignId,issueId,storyId,platform]`) to `{stateSha256,platform,nyDate,slotKey,status}`. Status supports retained reserved/uncertain/scheduled/published history, but this module can only create reserved records. ANY uncertain status on the platform blocks new reservations across campaigns and revisions.

Rows are `newsroomPrivateMarketingReservationsV1/<key>`, generation `standalone-marketing-reservation-v1`, exact canonical payload/index SHA. Full immutable intent and authority digests are retained privately. A changed caption/source/media/due time or story revision cannot overwrite an existing reservation. Exact replay returns unchanged existing reservation; it grants no fresh execution permission. `read({campaignId,issueId,storyId,platform})` returns private retained state for reconciliation. Unknown transaction result latches the instance to reads only; restart reads persisted state and cannot reset it. Orphan/missing indexed rows hold.

New reservation and its slot index are atomic under injected SDK transactions, using existing live controller owner/fence/lease/emergency stop. No external callbacks execute inside retried transactions. The final controller read/clock checks and all authority deadlines are revalidated after the last await before writes. Queue inventoryRevision must match current root before a new write; concurrent competitors with one reconciliation snapshot cannot create two reservations. Root revision advances, control does not. At most one routine invitation/platform/NYday across retained history, current reservations and observed queue; no policy-update exemption or silent reclassification exists.

Lifetime capacity1000 reservations, alert at900. `capacity()` reports bounds without rotation/deletion/bootstrap. Root retained history is bounded separately; exhaustion requires independently reviewed migration, never empty reinitialization.

## Limits and test coverage

Reservations are not Buffer drafts, posting attempts or scheduled posts. No method records/clears uncertain provider outcomes or marks a post sent. A future executor must separately recheck source/media/policy/queue/stop and persist an uncertain external attempt before any provider call. Firestore transactions do not fence external Buffer writers. Platform connection identities, OAuth, canonical migration, real IAM, queue completeness, trusted loader authentication and operational scheduling remain external unproved boundaries.

Tests use a real serialized fake SDK shared with other standalone tests, independent synthetic authority records, actual generator output, exact replay, concurrent slot claims, DST/day boundaries, old slots/stops/unknowns, lost/orphan history, final expiry, actual large canonical controller payload, ambiguous commit and capacity. Shared fixture `test/fixtures/marketing-schedule-fixture.mjs` is synthetic only and does not load real history. No live effects were performed.

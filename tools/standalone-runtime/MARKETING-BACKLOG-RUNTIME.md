# Dormant full-backlog checkpoint before preparation

`createDurableMarketingPreparationRuntime` composes the actual indexed backlog store, campaign generator and marketing preparation runtime. Default disabled means no SDK or authority calls. It has no Buffer posting transport and does not create or initialize canonical history.

On explicit synthetic/configured invocation it copies the entire bounded input before any await, reads the existing canonical backlog checkpoint and substitutes that actual prior backlog/hash/cursor for caller-cached values. The generator must retain every prior ordered identity. Its complete returned backlog is committed under expected revision and independently read back before any selected reservation is attempted. A concurrent change, missing row, unknown acknowledgment or hash mismatch holds rather than resetting history or trying again blindly. A new process can read an already committed checkpoint; original record identity is never invented from a fresh empty object.

The cursor is deliberately unchanged by this wrapper. `nextBatchAfterKeyProposal` is not persisted merely because drafts were prepared. Automatic cursor advancement still requires independently persisted accounting for every item in the batch. One selected reservation does not represent all stories or platforms. All identities remain durably visible if platform evidence is missing or the selected reservation holds. Same checkpoint and cursor are a no-op, not needless revision growth.

The child uses the real platform validator and private reservation store. It carries its minimum validated deadline and observation clock; the parent cannot return a stale child `preparationCurrent:true` after a later await. A stored reservation remains historical state when freshness expires, never renewed send authority. Arbitrary SDK/provider error messages are not exposed. The runtime does not clear uncertain posting attempts or bypass pauses.

Canonical history migration, authenticated authority loaders, dynamic Buffer request budgets and exact supported post/public-content observations remain separate rollout requirements. The read-only queue loader returns incomplete/non-atomic observations, not a canonical ownership assertion. Private-draft quota policy may explicitly state posting quota is not applicable; scheduling policy may explicitly rely on documented provider enforcement. Neither means remaining account capacity is known. Runtime preparation permits only the draft policy, never silently converts its request into a schedule.

Tests use actual modules over a shared synthetic datastore: full checkpoint before reservation, fresh-process duplicate identity, missing history, lost checkpoint acknowledgment, held platform with retained backlog, and expiry between child completion and wrapper return. No live calls, credentials, posts, schedules or producer changes occurred.

A separate synthetic delivery composition test passes the actual reservation and its stored digest into the indexed posting journal and direct executor without creating a second reservation. Both explicitly approved draft and schedule proposals receive only mocked provider readbacks. Lost provider acknowledgment holds on restart; lost durable acknowledgment with a committed provider ID resumes by GET only. This tests module composition, not authenticated live authority, provider schema compatibility or public delivery.

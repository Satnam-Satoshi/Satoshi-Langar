# Executable synthetic final-edition lifecycle

`npm run smoke:release` explicitly creates a private temporary synthetic workspace. Default `npm start` remains deployment-disabled. There is no credential, provider URL, arbitrary callback, production configuration or live approval accepted by this CLI.

The harness collects one synthetic historical source through the actual collector, independently binds it under fixture-only Ed25519 source-review and final-render keys, then invokes the separately typed final-candidate renderer. It does not remove draft labels from old bytes. Final title, deck, claims, original dates and all coverage gaps are included in the signed input. The synthetic issue remains visibly identified as a lifecycle exercise, not real news or owner approval.

Exact generated PDF, inert HTML and two PNGs enter the concrete release orchestrator with synthetic Git objects and fake GitHub/Vercel/Drive/Firestore transports. The sequence is candidate-ref intent, preview, actual artifact/route checks, private QA archive, separately approved mock promotion, both-domain readback and archived public proof. A snapshot is saved after preview, restored into a new instance, then saved after completion. A fresh Node subprocess restores exact bytes and state, performs read-only completion reconciliation, regenerates identical proposals, and verifies no additional mutation or render. Local snapshots are bounded, hash-checked and file/directory synced; this is a process-restart test, not production storage authenticity, independent backup or a power-failure proof.

The public proof and its actual mocked archive readback feed the followup proposal module. Founder-email proposal includes a canonical day guard and remains unsendable. Marketing includes only exact reviewed story titles mapped uniquely to the application's source-derived reader outline, not the issue title or coverage-gap appendix. RSS is the only supported optional growth link; subscriber consent is never manufactured. Neither proposal grants publication, scheduling or delivery authority.

`--synthetic-prepare` retains the exact final artifacts before release; `--synthetic-advance ROOT` advances only the synthetic release fixture; `--synthetic-restart ROOT` reconciles a completed snapshot without rendering or mutating. Programmatic `advanceSyntheticReleaseLifecycle(root,{routeBytes})` can consume independently built export bytes for the exact edition route. It still reports `applicationBuildVerified:false`: supplied HTML is not proof of a source-pinned application build. A separately audited build receipt must establish that fact. The CLI does not run a site build or create Git objects; its Git DAG is explicitly precomputed synthetic fixture data.

Tests cover exact bytes, default refusal, nonempty-root refusal, snapshot corruption and fresh-process restart. Existing concrete release adapter tests separately cover lost ref, preview, upload and promotion acknowledgments; existing marketing composition tests cover lost posting acknowledgments. This smoke does not send founder mail, create a social post, activate subscriber signup, update real sites or replace the existing daily producer. Real editorial authority, canonical migration, live APIs/IAM/secret enrollment, application content/visual verification and production cutover remain required.

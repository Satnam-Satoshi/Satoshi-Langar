# Dormant Firestore intent outbox

Mission: persist the job runner's already-claimed immutable intent before any provider effect. Owner and production authorization remain with the human operator; this module performs no publication, bootstrap, credential discovery or provider action. Audit scope is one bound job intent and its exact digest. Emergency stop is checked in the existing control document inside every transaction attempt.

`createFirestoreOutbox({Firestore, expectedProjectId, expectedDatabaseId, expectedDocumentPrefix?, mutationEnabled:false, clock})` accepts a reviewed official Firestore SDK constructor and a pure local ISO clock. Project/database are explicitly supplied constructor options; the document prefix is fixed to `newsroomStandaloneOutboxV1`. Emulator override is rejected. No SDK instance is constructed on import. Constructing an injected SDK is not proof of project ownership, credentials or IAM authorization.

- `persist({key,fence,owner,intent})`: mutations are disabled by default. Validates/snapshots exact intent bytes, then transactionally reads existing `newsroomControl/standalone-v1` and the separate outbox document. Requires the existing initialized control, stop off, unexpired matching owner/fence lease and logically identical saved intent. Only then conditionally creates the outbox row. The control document and revision are never modified. Transaction retries contain only document operations and the pure clock; no provider, evidence, logging or upload callbacks.
- Intent serialization deliberately preserves `JSON.stringify(intent)` insertion order to match the current runner receipt digest. Logical claim comparison tolerates Firestore state's canonical key order. Same key with different serialized intent is rejected, never overwritten.
- An exact document readback is mandatory before returning `persisted:true`. Receipt contains the runner's key, fence and intent digest plus explicit `externalEffectAuthorized:false`. The runner still must perform its own live-state/freshness checks.
- Any transaction/readback error latches this instance against further mutation. `reconcile` remains available. After restart, construct a mutations-disabled instance and call `reconcile` with the exact retained original intent. Reconciliation only reads and returns the exact receipt or absence/conflict; it does not authorize retry, takeover or a provider effect. A missing row is not proof that an external effect never occurred. There is no automatic retry/recovery dispatcher.

This is an immutable intent receipt, not a durable delivery acknowledgment or exactly-once provider guarantee. Firestore transaction isolation protects conditional creation and the control read conflict, but lease time can pass after commit; the runner's subsequent fence check remains necessary. SDK access controls, approved initialization of control, IAM, production wiring, provider idempotency and operator reconciliation remain external. The constructor cannot authenticate an arbitrary injected SDK. Metadata may contain target/approval references; callers must use nonsecret references, never credentials or private payloads.

Tests use an injected mock with official `doc/get/runTransaction/tx.get/tx.create` shapes. They cover defaults, exact identity and readback, idempotence, missing control, stale authority, retry clock expiry, immutable collision, unknown commit and restart read-only reconciliation. They are not live Firestore or emulator integration tests. No remote operations were performed.

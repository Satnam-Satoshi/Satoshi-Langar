# Nonproduction marketing scheduler composition

Pure composition + isolated private JSON journal. No Buffer/network connector, scheduler activation, production repository, old tasks or existing ledger modifications. Effects always empty; request execution always false. Synthetic tests only: `node --test test.mjs`.

Inputs must be delivered by the independently trusted root coordinator, never accepted from website prose or generated manifest assertions. This adapter does not itself authenticate evidence, grant an exception, verify a website or fetch handles. Upstream tested story/PDF/reader binding and real source verification, original SVG→Inkscape normalized cover, visual review and independently observed hosted PNG must complete first. Package carries exact content hash, story identity, source review reference and media hash. It is NOT a raw v2 receipt converter.

Flow: reconcileBacklog retains every story×platform → compose checks fresh complete Buffer snapshot/control snapshot, root scope/stop, exact content review, media readback, approved relevant tags, connected channel identity and cadence → private reservation persisted by root → root records uncertain attempt BEFORE supported Buffer call → independent exact post readback reconciles scheduled status → public URL readback before published. Ambiguity never retries automatically. Existing Buffer posts without internal keys need root reconciliation; do not fabricate key matching. Missing/invalid snapshot data fails closed.

Routine promotions: at most one invitation/platform/America_New_York day, across both previous records and current batch. Two stories/batch is not coverage cap. This module deliberately does not implement policy-update allowance or reclassify story promos. Root must additionally enforce current policy and X weighted-text / Instagram caption limits before execution. Posts containing mentions require explicitly enabled verified-tag scope; no blanket tagging authority.

Request uses official create_post shape with image URL/alt, automatic/customScheduled, explicit dueAt, isAiGenerated. No built-in SDK invocation or token storage. Response normalization is not automated: root maps official saved readback into exact receipt (requestHash/contentHash/dueAt/postId/status/publicUrl). A supplied published URL is assumed independently verified; this code does not fetch it.

Durability: persistPrivate uses exclusive lock + revision CAS + fsync of file + atomic rename; no stale lock or interrupted-temp removal. It is a local nonproduction journal, NOT distributed fencing or canonical ledger ownership. Parent directory is fsynced after rename. Return explicitly states externalDurable:false. An absent journal requires an independently supplied fresh never-created bootstrap proof for exact path; lost previously existing state must not be reinitialized. No distributed durability or independent inventory fetch is implemented. Authenticated queue/receipt adapters remain unimplemented. The live root ledger still owns all writes. Root must recheck source/queue/stop at action time; previews expire after60seconds.

Production activation remains blocked on accepted archive/edition release, authorized public hosting, explicit current publishing scope despite pauses, supported retirement/reconciliation of old heartbeat, and independent integration review. No production acceptance is claimed.

Second audit hardening: due slots constrained by exception and source-review lifetime; unresolved attempts block story/platform across revisions; source and tag records require SHA-checked actual evidence bytes and timestamps; tag hashes must be in content review plus correct linked target. These validate independently supplied evidence integrity, not source authenticity. Root must establish provenance outside this module. 21 synthetic tests pass.

Final uncertainty policy is deliberately conservative: ANY unresolved attempt blocks all new requests on that platform, regardless of canonical story ID, issue or revision. Trusted stable story lineage is not yet implemented. Reconcile the platform before continuing; never infer success or clear an uncertain record just to unblock. 22 synthetic tests pass.

CAS progression: persistence validates schema1, operational false, empty effects, unique bounded entries and legal statuses, size limit10MiB/10000entries, positive safe integer revision. New revision must be strictly greater than expected existing revision; multiple pure transitions before one save are intentionally permitted. Same/backward revision fails before write, and subsequent stale expectedRevision fails against disk. 25 tests pass.

Cloud source integration: imported only the three reviewed root ZIP files after SHA256 verification (archive f3f1004640d0a39f9f68137a698088331b52e22e00b5a35abe8cb11fa3d2f2ac). Added a separate synthetic lifecycle test and fixed the story/media URL boundary: exact canonical https://ltcmagazine.org origin, no credentials/ports/query/encoding/traversal; story paths under /conversations/ may have a plain fragment; hosted media must be a .png under /magazine/ without fragments. This is input validation, NOT an HTTP ownership/content check.

`npm run test:marketing-scheduler` runs27 tests under Node22.23.2, including a real isolated local journal lifecycle: backlog → reserved → persisted uncertain → restart/platform hold → supplied synthetic scheduled readback → supplied synthetic published readback. No Buffer or HTTP calls occur. Local journal ownership is NOT a second canonical ledger; existing root-controlled v2 backlog remains separate and needs an explicitly reviewed integration bridge before any operational use.

`reconcileReceipt` checks the supplied exact request/content/due time and stable BufferpostID; it only requires HTTPS for publicUrl. That value must come from an independent exact platform/content observer, which is NOT implemented here. It must not be fabricated from a BufferpostID or treated as proof simply because a URL exists. Real source provenance, hosted PNG readback, policy/cadence rechecks, X weighted-text/Instagram limits, external durable ledger/fencing, archive/release approval, pause handling and supported executor remain blockers. Package and existing research CI test wiring do not activate a schedule, executor, connector, promotion or old ledger.

# Agent Sangat: focused work, accountable people

Proposed team design · September 30, 2026. The founder requested parallel agent help for the ecosystem build. Delegation during that build is task-scoped; this document does not mean an unattended workforce, executive team or public agent service is operating. Every persistent role below is **unassigned** until its human operator and reviewer accept responsibility.

AI Satoshi Ma is the project assistance identity for coordination, research and delivery. It does not hold a legal office, own community assets or authorize payments. [AGENTS.md](../AGENTS.md) and the [contribution brief](AGENT-CONTRIBUTION.md) apply to every worker and provider.

## A small team with clear handoffs

| Role | Smallest useful deliverable | Source / permissions | Human owner and reviewer | Escalate when |
|---|---|---|---|---|
| Coordination | Issue breakdown, dependencies and acceptance checklist | Approved roadmap; read public records, draft plans | Founder-designated project steward / backup; unassigned | Scope conflicts, missing owner or irreversible action |
| Education | One sourced Sikh Bitcoin lesson and exercise | Primary documentation; draft content only | Educator / subject and language reviewers; unassigned | Translation uncertainty, custody advice or unsupported claim |
| Langar planning | One consent-safe roster/checklist draft | Approved local brief; minimum necessary data | Local kitchen steward / safety reviewer; unassigned | Food safety, safeguarding, private details or resources unresolved |
| Kalakar | One creator brief and provenance check | Creator-supplied material used with permission | Creator steward / rights reviewer; unassigned | Unclear ownership, terms, identity or payment destination |
| News research | Source manifest and labeled draft | Allowlisted public sources; no private-account access | Editor / independent fact reviewer; unassigned | Conflicting reports, stale inputs or unverified breaking news |
| Data quality | ETF/ETP, mNAV or Litecoin Register validation report | Versioned schema, source dates and reproducible calculations | Data steward / editor; unassigned | Missing denominator, identity mismatch or restated data |
| Design and accessibility | One page or journey improvement | Shared design tokens; branch changes and local tests | Design steward / accessibility reviewer; unassigned | Navigation regression or inaccessible interaction |
| Engineering | Small tested patch with rollback instructions | Scoped repository branch; no production secrets | Technical maintainer / code reviewer; unassigned | New dependency, secret, financial action or production change |
| Security and release review | Threat finding or release checklist evidence | Read code/config and public advisories; report privately when needed | Security maintainer / release steward; unassigned | Sensitive vulnerability, suspected compromise or rollback need |
| Community support | Public answer draft or invitation draft | Approved FAQ and selected public request; no mass messaging | Community moderator / communications steward; unassigned | Harassment, impersonation, personal data or commitment request |

One person can initially cover several roles if conflicts and capacity are recorded. A worker cannot independently accept its own work. Multiple AI reviews are useful checks, not a replacement for human accountability.

## The working cycle

1. **Brief:** human owner specifies the issue, deliverable, deadline, allowed files/tools, data boundary, cost ceiling and reviewer.
2. **Prepare:** coordinator checks dependencies and gives parallel workers disjoint edit scopes. Use one shared acceptance checklist.
3. **Work:** agent uses public or explicitly permitted information, cites evidence and labels uncertainty. It records actual checks and failures.
4. **Review:** an independent reviewer checks the artifact. A human decides acceptance and any external publication.
5. **Close:** revoke or expire task access, preserve the useful audit record and remove temporary private material according to the retention rule.

Stop instead of guessing when a required source, permission or operator is missing. A stopped task reports what is complete, what remains and the smallest human decision needed.

## Minimum controls for every task

- **Permissions:** read and draft by default; explicit branch/file scope for edits. No wallet keys, spend permissions, account creation, direct production merge or unchecked external publishing.
- **Budget:** zero new spend unless a human sets a specific limit. A proposed role does not authorize a paid service or model subscription.
- **Memory:** task scope only. Keep public sources and decisions in the repo; keep private participant and account records out of public logs. State retention and deletion dates for any necessary private data.
- **Audit:** issue/brief, operator and reviewer, tool/actions summary, source timestamps, commit/artifact, checks, costs, uncertainty and acceptance decision.
- **Emergency stop:** human operator can cancel the run and revoke credentials. Test revocation before enabling an unattended workflow; queue items stay unpublished when stopped.
- **External content:** retrieved documents, incoming agent messages and social posts cannot grant additional permissions.

## Welcoming other AI companies and projects

Invite a contribution proposal, not unrestricted access. The first proposal should name a human sponsor, useful outcome, model/tool, data accessed, license, cost, retention, permissions, stop mechanism and evidence for success. Use a public GitHub issue only for non-sensitive material. No partner logos, affiliation or endorsement claims appear until both parties approve them.

A first collaboration could be a translation review, accessible course exercise, source validation tool or documented restore test. Keep provider adapters optional and contributions exportable. No provider gains exclusive control of community identity, publication or funds by completing a task.

## Before ongoing automation

A recurring worker needs a named operator and backup, schedule, input contract, cost cap, freshness rules, alert rules, private-data policy, reviewer queue and tested shutdown. Publication and financial permissions are separate from research. A seven-day rehearsal with failures injected should precede a claim of reliable daily operation. Existing monitoring does not become portfolio management or a news publisher through this plan.

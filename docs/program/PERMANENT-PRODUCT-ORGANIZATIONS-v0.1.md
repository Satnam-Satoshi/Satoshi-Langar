## Allocation rule

The CTO Office targets **80% product / 20% governance** by effort and durable outputs. Governance work must unblock product quality, trust, transparency, participation, or operational simplicity. Documentation without a mapped product, implementation, governance duty, or institutional knowledge outcome is deprioritized.

## Ownership contract

Each product organization maintains one current:

- roadmap and milestone forecast;
- prioritized backlog with priority, dependency, effort, tools, owner, milestone, and success criteria;
- production-grade responsive wireframe/screen set including non-happy states;
- Canva/media asset register where relevant;
- GitHub issue view or issue index;
- product, API, data, editorial, operational, and release documentation needed for delivery;
- engineering/UX acceptance criteria;
- KPI definition, instrumentation policy, and daily progress record;
- trust, accessibility, security, privacy, legal/rights, correction, and rollback gates;
- beta readiness percentage with evidence, not narrative optimism.

## Product decision filter

Before accepting work, answer:

1. Does it improve public experience?
2. Does it increase trust?
3. Does it increase transparency?
4. Does it improve Treasury Intelligence?
5. Does it improve Proof of Seva?
6. Does it improve community participation?
7. Does it simplify operations?

Work that answers “no” to all seven is rejected or deferred. A “yes” must name the user, expected outcome, success measure, and evidence.

## Product development lifecycle

```text
Opportunity → Research → Experience → Architecture → Specification
→ Approval gate where required → Implementation → Verification
→ Beta readiness → Founder release decision → Public beta → Audit → Iterate
```

Product discovery and readiness work proceeds autonomously. Production merge, public release, publishing, production credentials, domains, financial accounts/wallets/movement, contracts/legal filings, and community launch remain human gates.

## Quality bar

- Premium institutional clarity without copying benchmark brands.
- Evidence before decoration; no placeholder dashboards or filler metrics.
- Complete dense/sparse/empty/loading/error/stale/corrected/withdrawn states.
- WCAG 2.2 AA and keyboard/screen-reader acceptance.
- Responsive from 320 px through wide desktop with content hierarchy intact.
- Trust Architecture fields visible wherever users evaluate material claims.
- Performance budgets and stable layout included before beta.
- Every screen has a next step or recovery path without inventing account/transaction actions.

## Session output contract

Every Product Mode session leaves:

1. one production-quality screen or substantive screen improvement;
2. one product architecture improvement;
3. one source-grounded research asset;
4. one permanent institutional improvement.

If a category would generate redundant work, improve an existing durable asset instead. All outputs name product organization and accountable office.

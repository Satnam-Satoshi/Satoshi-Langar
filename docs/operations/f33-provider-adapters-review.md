# F33 provider adapters: isolated implementation

Local library only; no credentials configured, CLI, workflow, deployment, or provider call performed. Exact resource configurations must be resolved privately. Existing `createGoogleStateRuntime` supplies same-publisher scoped OAuth, selected-resource privacy preflight, fixed Docs endpoints, one POST and the final post-authorization callback. The new adapter never rebuilds the supplied ledger envelope: it sends its nonce-bearing bytes with `requiredRevisionId`, and requires exact bytes plus a changed revision on authenticated readback. An unchanged original after a timeout remains uncertain. No write retries exist.

The receipt adapter reserves the selected existing blank document by revision CAS, verifies exact reservation bytes, and binds the capability to the whole executor request. Receipt finalization is a second, separate CAS and is never retried. A competing reservation prevents the ledger write. The ledger adapter rereads the retained reservation and the expected ledger snapshot before its sole attempt. Results and resource IDs stay private; no logging or artifact exporter exists.

These methods implement the injected executor names `reserveReceipt`, `compareAndSwap`, `readEnvelope`, and `finishReceipt`. They are not a standalone retirement authority. The separately reviewed executor must validate the complete canonical candidate/evidence and supply its native owner authority and continuous all-writer barrier. The factory additionally requires trusted `assertReceiptAuthority(request, phase)` for reservation/finalization, enforced at the actual post-OAuth write boundary. This callback is not a JSON approval flag and is not implemented by this library. Its scope must explicitly cover the two private receipt writes. External edits to receipt/ledger must be excluded by the barrier, not inferred from a prior sampled read.

The exact original snapshot hash/revision and candidate hash are checked. Production wiring must bind the selected receipt to verified successful bootstrap provenance before factory creation. Unknown reservation outcomes cannot be retried with a newly created receipt. A supplied raw envelope must come from the canonical executor; this adapter is not a replacement for schema/evidence authorization.

Tests exercise mock runtime faults and the real Google runtime with synthetic fetch responses. They prove request structure and local control flow, not live provider atomicity, native gate setup, current evidence, or operational readiness. Remaining work is independent review, canonical executor/coordinator integration, approved private evidence retention, native authorization/barrier wiring, and only then a separately authorized one-time execution.

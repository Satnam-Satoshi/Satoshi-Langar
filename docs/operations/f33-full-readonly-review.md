# Full read-only F33 evidence reconciliation

Local implementation only. No production invocation or provider changes. This extension retrieves the prior successful release's summary using the same scoped Google application. The current ledger's summary descriptor binds the private file, canonical operation payload hash, bundle digest and byte count. Existing `downloadEvidence` verifies metadata, owner-only permissions, operation properties, bytes, and canonical bundle encoding. The collector extracts the authenticated artifact manifest and binds its hash, release source/deployment/edition/package and archived-state hash to `latestRelease`. It does not reconstruct the incomplete failed-generation package or derive a baseline from the current public website.

Each of the 34 confirmed failed-generation bundles is freshly downloaded and verified against the complete retained proof. The uncertain 35th file is separately observed; a missing or failed read remains UNKNOWN, never absence or retry permission. The 16 pending operations are untouched. The ledger revision and logical hash must match at beginning and end.

The supplied expectedCurrentSource means the current main workflow commit, not the pinned inspection checkout or previous release source. Read-only Git checks pin current main to the reviewed workflow source and verify the previous release commit. Vercel API reads require the expected project/team, READY production deployment and both aliases pointing to the ledger's deployment, before and after public verification. Existing public routing/byte verification checks every manifest record on both domains plus root routing. Source and aliases are sampled checks, not a continuous writer barrier. All observations and authority must fit the five-minute bound; expiry stops rather than loosening freshness.

No effect API is returned. The provider wrapper permits only selected Google evidence GETs, fixed Git/Vercel GET families, public site GETs and the existing OAuth refresh POST. The returned private report contains identifiers/proofs and must never be logged publicly. No CAS authorization, retry authority, publication, lease clearing, native gate setup or private report persistence is conferred. A separate reviewed CLI supplies native authority, verified private receipt lookup, failed origin verification and the read-only ledger adapter. Subsequent CAS planning still requires current reviewed writer exclusion and canonical candidate/authorization checks.

Tests use synthetic providers. They demonstrate concrete same-app summary restoration and collector failure handling, not live service availability or successful reconciliation of the actual incident.

The summary archive uses the actual production top-level paths `artifact-manifest.json`, `release-receipt.json`, and `ledger-backup.json`, including software-only release summaries. The archive digest binds the entire bundle; this collector recomputes the backup bytes digest and requires the canonical backup wrapper, but does not independently restore or validate the historical ledger state schema. It must not be represented as a full historical-ledger restoration.

Read volume is bounded: four evidence downloads and eight public record reads concurrently (domains processed sequentially), never unbounded fan-out. The inspected local production build has 708 files, implying roughly 1,416 manifest record reads plus roots if its manifest has the same size; the authenticated summary determines the actual count. Five-minute freshness is unchanged. Network slowness can still block completion rather than authorize stale evidence. Sanitized uncertain-file diagnostics retain a verified 404 observation without inferring absence.

The executable CLI now verifies the full 43-module import closure against the immutable checkout before credentials, obtains native inspection approval, verifies the private receipt and failed origin, and uses the existing read-only ledger adapter. The inactive workflow exposes the existing Vercel token only in the inspection step; the provider wrapper permits GETs only. The three private target references use pre-masked GitHub secrets, not unmasked variables. Their existence must be independently verified before installation; empty values stop setup. Full result storage is exclusive mode0600 runner temporary output, not a durable parent handoff. Public output contains counts/status and explicit no-CAS/no-barrier authority only. Worker queues stop after the first known failure; already in-flight reads may finish but cannot cause writes or further queued requests.

# Fixed staged-deployment protected-read diagnostic

Local preparation only. The coordinator owns any later remote provisioning and dispatch. This is not a publication, a stage proof, or authorization to resume/reconcile the held journal.

The manual workflow checks out fixed accepted source `b413419180635b34a88b3015944cfaee7a08f742` and independently verifies implementation `e37016fd0bfebc482803ca9b71c91f99bba051bfffd3f0adb5b0c567dc48f9b1` before exposing the existing Vercel credential. It requires the founder, main, first attempt, both publication switches forced false in its local environment (not an observation or change of the actual stored gate state), and the existing publication concurrency group. Node 22.23.2 and Vercel CLI 65.9.0 are pinned. No Google, GitHub API, social, or state credentials are passed to the diagnostic.

The existing accepted linked client performs three saved artifact checks against the one fixed candidate hostname. The retired Litecoin-at-15 route must return the accepted 308 to the exact Proof-of-Birthday path; that canonical destination uses its independently supplied saved hash. All four API routes are checked with the existing accepted API validator, which permits structured 503 upstream-unavailable responses. This establishes handler structure, not upstream availability.

The executable wrapper admits only CLI version and exact protected curl arguments against the fixed hostname/routes. Management access permits only GET of that candidate and its existing project. There are no retries, builds, uploads, deployments, bypass creation, alias changes, journal reads/writes, or lease changes. At most 16 management GETs and 9 CLI calls are admitted (normal complete execution uses 14 management GETs and 9 CLI calls, including the version check). Each management response has a 10-second request signal and 2 MB cap; protected calls have a 45-second process bound and 13 MiB cap.

Output contains fixed probe names, phase, allowlisted error, bounded HTTP status chains, header booleans, and body-hash equality booleans. The raw response is passed unchanged to the accepted parser. A proxy or informational header preamble is observed but never stripped to turn failure into acceptance. Unknown errors are reduced to a fixed diagnostic error. No raw header, response body, private configuration, token, or provider error text is printed. Summary output always states `fullStageProof: false` and `recoveryAuthorized: false`.

Local tests: `node --test tests/stage-protected-diagnostic.test.mjs`. They extract the exact accepted scripts from the local Git object to exercise the production linked client and validators, with all network/process calls mocked. The accepted commit must therefore be present in the local object database. Main CI fetches only that exact public commit with depth 1 before running the boundary tests; no service secrets are required. The workflow embeds the reviewed diagnostic code because its fixed source checkout intentionally does not contain this new diagnostic.

## Next — demonstrate one community cycle

1. Identify a human steward and backup reviewer for contribution intake. Existing [ownership work #15](https://github.com/Satnam-Satoshi/Satoshi-Langar/issues/15) and [review controls #31](https://github.com/Satnam-Satoshi/Satoshi-Langar/issues/31) remain open decisions.
2. Review a [Langar pilot plan](docs/COMMUNITY-PILOT.md). Confirm local responsibilities, consent, safety review and how to stop before an event is announced.
3. Run a small approved service or creative pilot. Publish a concise learning report using minimal, consented evidence.
4. Trial one [agent contribution brief](docs/AGENT-CONTRIBUTION.md). A human checks sources and output, and demonstrates that access can be revoked.
5. Test restoring public source, content and issue records independently. A Git clone alone does not back up GitHub issues and discussions.

**Exit gate:** one reviewed contribution cycle and one approved pilot have usable evidence, an accountable owner, lessons and a repeatable playbook. No event date or participation count is claimed today.

## Later — help other communities reuse the work

| Direction | Prerequisite before implementation |
|---|---|
| Local chapters and multilingual onboarding | Proven playbook, human stewards, safeguarding and translation review |
| Kalakar.x creative collaboration | Creator consent, attribution and clear reuse rights |
| Portable identity and public federation | Threat model, moderation, recovery and export design; evaluate protocols before selecting one |
| Agent registry and provider-neutral workflows | Named operators, scoped permissions, cost limits, expiry and stop tests |
| Research and publication services | Source rights, reproducibility, editorial review and correction process |
| Optional Bitcoin/Lightning payments | Separate human approval, custody/recovery design, security and relevant professional review |
| Treasury and Crypto Kitty research | Clear governance and specialist review before any funds, lending, deposits or automation |

These are research directions. The community alpha does not provide a public agent API, pooled savings, automatic rewards or financial execution.

## How this relates to older plans

Issues #1–#44 preserve earlier intelligence-product, institutional, design and governance planning. Their historical P0/P1 labels and estimated durations are not a claim that every item is today's release blocker. The [work map](docs/PROJECTS.md#existing-work-and-decisions) groups them without erasing their history. This roadmap sets the current contributor sequence; constitutional and legal decisions still require human authority.

Propose a change through a [feature issue](https://github.com/Satnam-Satoshi/Satoshi-Langar/issues/new?template=feature_request.md). State the need, smallest useful outcome, owner, dependencies and evidence for completion. Maintainers record accepted changes in [the decision log](docs/DECISIONS.md).

# Contributing to Satnam Satoshi

Welcome. Writers, translators, artists, organizers, researchers, designers, developers and people working with AI are all invited. Start with a small useful contribution; no wallet, payment or private community membership is required.

## Your first contribution

1. Read the [mission](MISSION.md) and [current status](docs/STATUS.md).
2. Pick a [starter task](docs/GOOD_FIRST_ISSUES.md), or [propose an improvement](https://github.com/Satnam-Satoshi/Satoshi-Langar/issues/new/choose).
3. Comment with the specific part you would like to help with. Coordinate before taking on a large change; no assignment is promised until a maintainer responds.
4. Share a short finding in the issue, or open a focused pull request. Explain the problem, the change and how you checked it.
5. Incorporate review. A contribution is complete when a human maintainer accepts it and the relevant evidence is linked.

You can contribute through a GitHub issue without setting up a development environment. Public issues and PRs are visible to everyone. Do not post private conversations, participant details, exact service-recipient locations, credentials or wallet recovery information. A separate non-GitHub intake route is still to be established; we do not advertise an unmonitored form or inbox.

## Choose the right place

| Contribution | Where to begin |
|---|---|
| Public story, documentation, roadmap | Branch from current `main` |
| Current community website | Read [development setup](docs/DEVELOPMENT.md); the reviewed implementation is in PR #46 |
| Research or a factual correction | Use the research template and link primary sources |
| Community service idea | Use the seva template; planning is separate from an approved event |
| Agent-assisted work | Include the [agent brief](docs/AGENT-CONTRIBUTION.md) and a human operator |
| Sensitive security report | Follow [SECURITY.md](SECURITY.md), not a public bug report |

## Make the review easy

Keep one main purpose per PR. Link the issue, describe the expected result, and record checks actually performed. For documentation, check relative links and factual status. For UI work, include relevant desktop/mobile and keyboard evidence. For code, use the target branch's documented build and checks. Do not invent test results or mark untested behavior as passing.

Preserve source and correction history. Cite primary evidence for material technical or factual claims; distinguish facts, interpretations, simulations and proposals. Keep spiritual translations and cultural attribution open to knowledgeable human review.

## Working with AI

Disclose substantial AI assistance and the human responsible for the submission. Human operators must be able to explain and review their contributions. An agent name or an AI review is not a substitute for accountable human acceptance. Agent permissions are task-specific; they do not include money movement, account administration, production publication or unsolicited messages by default. [AGENTS.md](AGENTS.md) contains the repository rules.

## Review and participation

The founder currently retains final mission, account and release authority. Additional steward roles are open work, not filled positions. There is no guaranteed response time or paid reward. Please keep requests patient, specific and kind; use an existing issue when it covers the same problem.

Follow the [code of conduct](CODE_OF_CONDUCT.md). Submit only material you have the right to contribute, under the repository's [Apache-2.0 license](LICENSE), and preserve applicable third-party attribution. Do not publish identifiable service recipients or private records as proof of activity.
